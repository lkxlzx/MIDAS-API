## 1. 概述

**Buoy Checker SE**是基于 GEN NX 分析结果与用户输入的设计条件，对结构物在竣工状态及各施工
阶段的浮起（浮上，uplift/buoyancy）安全性进行验算的 Plug-in。验算所需的分析结果由 GEN NX
自动读取，从分阶段安全系数验算、到控制水位（可作业地下水位）推算、再到报告输出，全部在一个
连续的4步骤工作流中完成。

## 2. 问题定义

- 地下水位较高场地上，为防止结构物在竣工前（自重尚未充分积累的施工过程中）因浮力而上浮，需要
  按施工阶段逐个比较抵抗重量（结构体轴力 + 基础自重）与浮力，属于重复计算。
- 该验算必须取用 GEN NX 的分析结果（分层轴力、支座反力），在结果表与计算表之间来回誊抄的过程
  中，容易出现数据缺失与不一致。
- 为满足目标安全系数而反算“地下水位需要降到多少”（控制水位），手工操作也十分繁琐。

## 3. 目标用户

- 需要验算地下水位较高场地的结构物（含地下层的建筑等）逐施工阶段浮起安全性的结构工程师。
- 需要推算各开挖·浇筑工序的控制水位并反映到施工计划中的现场人员。

## 4. 核心概念 / 差异点

- **顶部状态提示条 + 脉动高亮效果**：显示4个步骤（①输入设计条件 ②确认联动数据 ③验算 ④报告）
  的进度状态，并对下一个输入字段做脉动高亮——与#7·#12·#16相同的新用户上手（onboarding）模式，
  在整个开发者生态中被反复采用。
- **GEN NX 结果自动联动 + 交叉验证**：按 Story 提取的固定荷载（D）轴力与基础支座反力，分别用
  不同的 API（层轴力合计表与支座反力表）各自取回，随后“对两个分析结果进行交叉验证，确认数据
  是否存在缺失与不一致”——例如自动比对最下层轴力与支座反力合计是否一致（画面示例：“Story
  最下层 35,914.93kN / 支座反力合计 35,914.93kN / 误差 0.00% · 相同”）。把两个互相独立的 API
  结果用作彼此的验证手段，是该 Plug-in 独有的设计。
- **支持底面标高不同的基础**：基础可按单基础或底面标高不同的多个基础分开输入（基础1：
  GL-5.0m，基础2：另设标高）——连带台阶的基础形状也一并反映，实时刷新浮力验算概念图。
- **浮力验算联动概念图实时可视化**：输入地下水位深度、混凝土重度、是否另加基础自重、基础
  面积·厚度·底面标高的瞬间，左侧概念图（地面 GL、上部结构轴力 D、基础厚度 T·自重、水头 h、
  浮力 W.P = q×A）即实时刷新，直观确认各输入值的物理含义。
- **分施工阶段的验算栈**：在默认的“竣工时”之外，可自由添加“分施工阶段”（例：施工至1F水平
  构件、施工至2F水平构件等），一次批量验算多个施工阶段。
- **详细计算结果透明公开**：各阶段以“01 竣工时 OK / 02 施工至1F水平构件时 NG”的方式汇总判定，
  点击后可逐级展开完整算式：上部结构轴力 D、基础自重计算、D.L 合计、水头 h 计算、浮力 W.P
  计算、目标抵抗力（SF×W.P）、UPLIFT CHECK 比较式，直至强度设计法（0.9D+1.6W ≥ 0）。
- **自动控制水位（合理地下水位）建议**：针对判定为 NG 的阶段，在“工程师采用水位”小节中，按
  “依据上述浮起安全性验算结果，建议将现场地下水位降至 GL- m 以下”自动反算出满足目标安全系数
  的控制水位并给出（原文第3项功能“反算满足目标安全系数所需的分阶段控制水位”）。

## 5. 工作流

### Step 0 — 在 Apps 中运行

- 在 GEN NX `Apps > My Work` 中运行 "Buoy Checker SE" → 运行前确认：确认 API Connection 状态，
  “请在已定义 Story 且已生成固定荷载分析结果的模型中运行。”

### Step 1 — 输入设计条件

- 输入地下水位标高（以 G.L. 为基准，例1.5m）、水的重度 γw（例10kN/m³）、混凝土重度（例
  24kN/m³）。
- “在前面单独累加基础自重”复选框。
- 基础信息：选择单基础或底面不同的多个基础 → 输入各基础分区的面积(m²)、厚度 T(m)、底面标高
  （GL-m）、埋入深度 H（自动计算）、水头 h(m)。
- “浮力验算联动概念图”实时可视化地上结构物·基础·地下水位·浮力 W.P。

### Step 2 — 确认联动数据

- “确认基础基准 Story”：用下拉框确认并修改各基础（基础1、基础2）对应 GEN NX 的哪一个 Story
  标高（例：基础1 → B1F·Level -5.0m）。
- 固定荷载（D）映射：在多个静力荷载工况（含 Self Weight）中选择要映射为固定荷载的工况（添加
  多个时求和）。在“交叉验证”小节中比较 Story 最下层轴力与支座反力合计，自动显示误差与不一致
  情况。
- 确认按 Story 列出的表格（Level、轴力 D、埋入 D 等）。
- 在**“联动原始数据”弹窗**中可直接点击5个取数项，查看原始 API 响应表格（见第6节）——与
  #7 ScaleUp、#12 OTChecker 相同的透明性设计。

### Step 3 — 验算

- 输入验算安全系数 SF（例1.20）。
- 在“验算施工阶段”表中，除“竣工时”（默认，全部 Story）外，用“+添加施工阶段”自由增加“分施工
  阶段”行，并逐行用下拉框指定“已执行的施工范围”（至B1F水平构件 / 至1F水平构件 / … / 至7F
  水平构件）。
- 点击“执行验算”→ 查看各阶段判定（OK/NG）汇总，并在“查看详细计算结果”弹窗中确认各阶段的完整
  算式（D.L 合计、W.P 计算、UPLIFT CHECK、0.9D+1.6W 强度设计法比较）。
- 示例：“01 竣工时 — 上部结构轴力 D=35,914.93kN，基础1 基础自重=0.50×24.00×400.00=4,800.00kN，
  D.L=40,714.93kN，水头 h=max(0, 基础底面-地下水位)=max(0, 5.00-1.50)=3.50m，浮力 q=h×γw=
  35.00kN/m²，浮力 W.P=q×A=35.00×400.00=14,000.00kN，目标抵抗力=SF×W.P=1.20×14,000.00=
  16,800.00kN，UPLIFT CHECK=40,714.93≥16,800.00kN → OK，0.9D+1.6W=0.9×40,714.93-1.6×14,000.00=
  14,243.44kN”——“02 施工至1F水平构件时”判定为 NG（因为轴力尚未充分积累的施工初期阶段）。

### Step 4 — 报告

- 输入项目名·公司名后，在“工程师采用水位”小节中确认并修改 GL- m 条件（控制水位），并按
  “以工程师采用水位 GL-2.00m 条件”应用。
- “浮起安全性验算报告”打印/PDF：输出含项目名、公司名、编制日期与验算概要的 A4 报告。

## 7. 输入数据规格

- **设计条件**：地下水位标高（以 GL 为基准）、水的重度、混凝土重度、是否另加基础自重。
- **基础信息**：单个或多个（底面标高不同）基础的面积·厚度·底面标高。
- **验算条件**：验算安全系数 SF、待验算的施工阶段清单（竣工时 + 任意数量的分施工阶段）。
- **前置条件**：已定义 Story 且已生成固定荷载分析结果的 GEN NX 模型。

## 8. 输出 / 生成结果

- 分阶段的浮起安全性判定（OK/NG）与详细计算依据（D.L、W.P、UPLIFT CHECK、强度设计法比较）。
- 满足目标安全系数的控制水位（工程师采用水位，GL- m）。
- “浮起安全性验算报告”（打印/PDF）。

## 9. 限制事项与局限

- 施工阶段看似只能按“施工至N层水平构件”这一规范化划分进行选择，能否细致反映框架以外的非定型
  施工顺序（例：仅先浇筑特定区域），画面上未能确认。
- 交叉验证看似只核对最下层轴力与支座反力合计是否一致，是否会自动指出其他楼层的细微不一致，
  画面上未明确显示。
- “工程师采用水位”由 Plug-in 计算出建议值并展示，但是否最终采用及数值调整须由用户确定——是
  判断辅助，而非自动确定。
