## 1. 概述

**AutoSteel** 是对 MIDAS GEN NX 模型的钢截面进行优化设计的工具。它从 GEN NX 的设计验算结果中
找出富余的构件，在标准 H 型钢规格阶梯（size ladder）上逐级下调以减少钢材总重量，并自动确定与
用户指定目标设计比最接近的构件尺寸。

## 2. 问题定义

- 在初始钢结构建模阶段，出于安全往往分配偏大的截面；而找出设计验算结果富余（强度富余率）较大的
  构件、在标准规格阶梯上逐级下调以减少用钢量的工作，构件数量越多就越发重复且耗时。
- 以手工逐个代入寻找与目标设计比（例：0.90）最接近的尺寸，效率低下。

## 3. 目标用户

- 希望削减钢结构物用钢量的结构设计人员，尤其是初始建模后处于优化阶段的现场人员。

## 4. 核心概念 / 差异点

- **在标准 H 型钢阶梯上逐级轻量化**：不是计算任意尺寸，而是从实际流通的标准 H 型钢规格清单
  （“阶梯”）中，把当前尺寸降到低一级的规格——确保只使用实际可下单·采购的规格。
- **以目标设计比为基准自动收敛**：只需输入“目标设计比 ratio”（例 0.90）一项，即自动判定超过
  （违反）该值的构件，并将其收敛到与该基准最接近的尺寸。
- **用锁定构件编号排除特定构件**：将特定构件编号（例：12、13、41）设为“锁定”后即从优化对象中
  排除（固定）——可以不动特殊构件（例：支撑节点相邻构件），只优化其余构件。留空则为全部对象。
- **轻量化 → 复核 → 上调（up-sizing）自动循环**：一旦下调的尺寸在复核中被判定富余不足（违反），
  就自动回升一级（上调），并以该状态“上调确定”后不再变更的历史管理型算法——不是单纯的向下搜索，
  而是双向搜索。
- **用8种状态标签实时可视化进度**：轻量化（下调）/维持/上调（上提）/上调确定/验证通过/失败·中止/
  排除——各构件经历了哪些状态、最终尺寸如何确定，全部可通过颜色标签追踪。
- **为保护原件强制另存副本**：开始优化时必定经过“此操作会伴随建模变更。保存副本后进行优化”的
  确认窗口，不触碰原始文件，而在 `.mgbx` 副本文件上进行优化——从根源杜绝误覆盖原件的事故。
- **恢复原状按钮**：对优化结果不满意时，用“恢复原状”按钮一键即时回退到优化前状态。
- **自行告知自动验证的局限（“诚实点”）**：把本次运行中未自动算出的验算项目，如挠度（Deflection）
  （“INACTIVE: GEN 在执行 DEFL_CHK+CODE-ANAL 后仍未算出挠度值(DEFA)。本次运行未验证挠度安全
  性”），在结果画面中显式警告，并要求对最长管理构件（例：7m）“务必以其他手段手动确认”——不隐藏
  自动化未能覆盖之处、向用户明确告知的设计哲学十分突出。

## 5. 工作流

### Step 1 — 连接

- 运行 AutoSteel → “在 GEN NX 中打开模型（副本）”并输入 MAPI-Key → 点击 [连接]。
- 连接成功后状态徽章显示为“已连接 · 模型构件 63 · 截面 2”（自动识别对象模型的构件·截面数量）。

### Step 2 — 输入目标

- 输入目标设计比 ratio（例 0.90）——“超过该值的构件判定为违反（0.5~1.0，必填）”。
- 锁定构件编号（逗号分隔，可选）——“所指定的构件编号将从截面尺寸确定中排除（固定）。留空则为
  全部对象”。

### Step 3 — 执行·安全

- 点击“开始优化”→ “此操作会伴随建模变更。保存副本后进行优化”确认模态 → 点击确认。
- 为保护原件，先将副本（.mgbx，例 `AutoSteel_사본_20260731.mgbx`）保存到其他路径再进行。

### Step 4 — 进度（反复重解析）

- 进度日志按顺序输出各构件的判定。示例：
  - “长细比保守验算 — 只拉构件 36根：针对转为受压的可能性，对长细比进行保守验算”
  - “轻量化 — H 400x200x8/13（36根）：强度富余 16% → 轻量化至 H396x199x7/11（每根节省
    -65.7kg）”
  - “轻量化 — H 400x400x13/21（27根）：强度富余 74% → 轻量化至 H200x200x8/12（每根节省
    -478.7kg）”
  - “上调 — H 400x200x8/13（36根）：复核结果富余不足 → 上调至 H400x200x8/13”
  - “上调确定 — H 400x200x8/13（36根）：上调确定 — 此后不再变更”
  - “上调 — H 400x400x13/21（27根）：复核结果富余不足 → 上调至 H250x250x9/14”
  - “上调确定 — H 400x400x13/21（27根）：上调确定 — 此后不再变更”
  - “验证通过 — 最终验证通过：强度·长细比无异常（挠度另行确认）”
- 即首次轻量化（400x200x8/13 → 396x199x7/11 等）若在复核中被判定富余不足，则自动上调一级
  （396x199x7/11 → 恢复为 400x200x8/13，或重新调整为 250x250x9/14），并以该值确定，如此反复
  重解析循环执行多次（观察到的案例至少2次以上）。

### Step 5 — 结果

- 最终结果卡片：总重（优化对象）34,397.1 → 23,834.7kg，**节省率 30.7%**（以整体模型为基准的
  节省率 30.5%，含非对象构件）。
- 各构件优化前/后截面对比表（构件名·截面号·材质）：例 `H 400x200x8/13` →
  `H-400X200X8X13`（未变更，上调确定的结果），`H 400x400x13/21` → `H-250X250X9X14`（轻量化确定
  的结果）。
- “剩余违反：无（强度·长细比满足）”。
- **需要确认的项目**（自动验证局限告知）：
  1. “挠度验算：INACTIVE — GEN 在执行 DEFL_CHK+CODE-ANAL 后仍未算出 DEFA。本次运行未验证挠度
     安全性。最长管理构件 7m — 挠度风险依然存在，务必以其他手段手动确认”
  2. “无设计验算结果的构件：0根 — 不属于自动轻量化对象，故保持原截面，需要手动确认”
  3. “只拉构件保守验算：36根 — 针对转为受压的可能性，对长细比作了保守判定”
- 可用“各构件前/后截面表 + [计算书保存(xlsx)]”导出。
- 结果不满意时，可用“恢复原状”按钮即时返回优化前状态。

## 6. 关联的 JSON API 端点

强烈提示其与 #8（ScaffoldModel）中确认的 KDS 41 30:2022 钢设计 API 系列使用同一端点：

| 执行钢代码验算（反复复核） | `POST DESIGN/STEEL/KDS-41-30-2022/CODE-ANAL` | [`25_Design_Steel_KDS41302022.md#23-designsteelkds-41-30-2022code-anal--steel-code-check-perform-강재-코드-검토-수행`](../../manual/zh-cn/25_Design_Steel_KDS41302022.md#23-designsteelkds-41-30-2022code-anal--steel-code-check-perform-钢结构规范校核执行) |
| 查询验算结果（富余率、是否违反） | `POST DESIGN/STEEL/KDS-41-30-2022/CODE-TABLE` | [`25_Design_Steel_KDS41302022.md#24-designsteelkds-41-30-2022code-table--steel-code-check-table-강재-코드-검토-표`](../../manual/zh-cn/25_Design_Steel_KDS41302022.md#24-designsteelkds-41-30-2022code-table--steel-code-check-table-钢结构规范校核表) |
| 截面变更（轻量化/上调） | `PUT /db/SECT` | [`04_DB_Properties.md#12-dbsect`](../../manual/zh-cn/04_DB_Properties.md#12-dbsect) |

- `DEFL_CHK` 在 `docs/manual/25_Design_Steel_KDS41302022.md` §1 `DCO`（Design Code Option）的
  Specifications 表中被准确文档化为“梁/柱挠度验算，Key: `DEFL_CHK`，Boolean，默认值 true”，
  由此确认日志中“GEN 在 DEFL_CHK+CODE-ANAL 后仍未算出 DEFA”一语原样引用了实际 API 字段名——这是
  本会话中连字段名都精确比对过的案例。
- ⚠️ `DEFA`（推测作为挠度结果值的字段名）在 `docs/manual` 中未能找到完全一致的文稿——推测为
  Steel Code Check Table（`CODE-TABLE`）响应中的某一明细列，但未确认。
- 轻量化·上调的判定算法本身（在标准阶梯上移动几级、何时确定上调）并非 API 提供的结果，而似乎是
  Plug-in 基于 `CODE-TABLE` 响应（富余率）自行实现的搜索逻辑。

## 7. 输入数据规格

- **目标设计比 ratio**：0.5~1.0 范围，必填。
- **锁定构件编号**：以逗号分隔的构件编号清单（可选，留空为全部对象）。
- **前置条件**：GEN NX 模型中须已执行钢设计验算（KDS 41 30:2022）（连接时自动识别为“模型构件
  63·截面 2”）。

## 8. 输出 / 生成结果

- 反映到 GEN NX 模型（副本 `.mgbx`）的优化后截面（`/db/SECT`）。
- 总重节省摘要（以优化对象/整体模型为基准）、各构件前/后截面对比表。
- 计算书（xlsx）导出。

## 9. 限制事项与局限

- **挠度（Deflection）验算在本次运行中未被自动验证** — 这是 Plug-in 自行明示的局限，优化后的
  截面即便满足强度·长细比，是否满足挠度限值仍需另行手动确认。尤其对大跨构件（例 7m 以上）该
  风险被特别强调。
- 只拉构件注明会考虑转为受压的可能性而对长细比作“保守”判定，因此这些构件的优化幅度可能小于
  其他构件。
- 本身没有设计验算结果的构件不进入自动轻量化对象而保持原截面，此情况同样需用户另行手动确认。
- 标准 H 型钢“阶梯”清单的具体规格范围（以何种目录为基准）在画面中未明确确认（⚠️ 未确认）。
