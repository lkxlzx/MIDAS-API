## 概述

CS 454 评估模型中的交通车道（assessment traffic lane），是人人都会去做、却没人喜欢的工作。CS 454 并不只使用一套车道体系，而是让三套体系共存于同一个模型中 —— ALL Model 1 的单辆车 3.0 m 车道、车队（convoy）用 2.5 m 车道，以及 ALL Model 2 用的 C/nn 车道（nn 由 Equation 5.18 计算，但 7.5 m 及以下的区段按表中的例外取值）。每条车道都要求给出：相对基准线（reference line）的位置、随构件局部轴方向而改变符号的偏心（eccentricity）、MIDAS 按 CS 454 实际应用值 1/3 存储的轮距（wheel spacing），以及车道所经每个单元各需一个的 Lane Item（长桥可达数百个）。再叠加特殊车辆（special vehicle）与正常交通共同通行的组合时，整个车行道都要重新布置。**CS 454 Auto Lane Generator** 代劳了这些算术与录入工作 —— 它先读取模型、在图纸上设定基准线，计算出所选荷载真正需要的车道，在平面·剖面两侧连同车辆一并绘制展示之后，才正式写入。

## 支持版本

`MIDAS CIVIL NX 2026 (v2.2)` — Plug-in 版本 `1.0.0`

## 主要功能

- **三套车道体系分开管理：** 把 cl 5.8·Table 5.9a 的 ALL Model 1（单辆车 3.0 m / 车队 2.5 m）与 cl 5.18 的 ALL Model 2（C/nn）分别生成为名称不同的套组，使各移动荷载工况各自选用相匹配的一套，剖面图中也以颜色区分，可并排比对。
- **同时体现 Equation 5.18 及其例外：** Table 5.18 的通式针对超过 7.5 m 的区段，其下的各行属于无法由公式复现的表中例外。故适用表格的区段查表取值，仅对超过 21.9 m 的区段以公式外延。
- **剩余区域（remaining area）条件处理：** cl 5.16 对剩余区域施加 5 kN/m²，而 cl 5.16.1 规定当评估活荷载不超过 7.5 t 时可取为不加载 —— 此时完全不生成车道，并一并显示依据条款。
- **特殊车辆与正常交通并排布置：** CS 458 组合工况要求把特殊车辆与其伴随的正常交通并排放入同一行（同时作用），并按 Appendix C3 令正常交通填满车辆未占用到的区域。
- **明确轮距的折算：** Appendix B 的实际轮距为每轴 1.8 m，但 MIDAS BS 移动荷载代码要求存储值取其 1/3（0.6）—— 面板与图纸上始终显示实际的 1.8 m，预览表中则同时给出两个数值。
- **Table 5.9a 最小间距自动告警：** 利用车道宽度减去 Appendix B 轮距后的数值与该表相邻车辆最小间距（3.0−1.8=1.2 / 2.5−1.8=0.7）恰好相符这一点，当随意放大轮距将构成违反 cl 5.13 时，连同计算依据一并告警。
- **人行道（footway）车道不予生成的条件：** 按 cl 5.30，人群荷载下加载长度超过 36 m，或绝对值超过 400 m 的区段，不生成人行道车道，并显示依据条款。
- **事故车辆（accidental vehicle）荷载条件判定：** 按 cl 5.27/5.27.1，仅对支承无有效防护设施（按 CD 377 标准的 higher/very high containment）的中央分隔带·verge·人行道的构件判定是否适用，判定时同时询问宽度与有无防护设施。
- **直接生成基准线：** 在曲线桥·斜（skew）桥等不存在可作测量基准的单根构件时，采用经过所选节点的既有梁，或新生成 10×10 mm 的虚拟基准梁链。
- **写入前全量可视化及按 key 删除：** 基准线·车道·设置效果在写入前先以图纸显示；删除操作因名称过滤器会造成整表删除这一 API 特性，故始终按确切的 key 执行。

## 使用方法

| 步骤 | 说明 |
| --- | --- |
| 1 | 在 CIVIL NX 中打开桥梁模型并运行 Plug-in — 连接信息自动设置，Validation Check 卡片报告 Base URI·MAPI Key 问题 |
| 2 | **Read model** — 一次性读取节点·单元·结构组·截面·既有车道·单位·移动荷载代码。无移动荷载代码的模型设为 BS（若已设定其他代码，不会在不告知将丢失什么内容的前提下擅自更改） |
| 3 | 选择 **Reference line** — 以推荐的线、输入单元范围或点击节点来指定测量偏心的基准线。报告是否复用既有梁·最小曲率半径，并在写入前以图纸显示 |
| 4 | **Lanes** — 在 ALL Model 1 各工况、ALL Model 2、短跨荷载、人行道、事故荷载、CS 458 特殊车辆、HB 车辆、特殊车辆组合中仅勾选所需项。只要求输入所勾选项真正用到的数值 |
| 5 | 定义横断面 — 输入按 CS 454 标准的车行道宽度（路缘石·隆起铺装·防撞墙之间，含路肩）以及自基准线到左侧路缘石的偏距（注意与 EN 1991-2 的方式不同），并设置评估活荷载等级 |
| 6 | 特殊车辆布置 — 指定按 CS 458 标准的车辆宽度（无法自动计算，需手工输入）与其在组合中的位置，以及作为对齐基准的路缘石 |
| 7 | 查看图纸 — 剖面图按实际比例显示路缘石面·车道宽度·车辆轮距，平面图显示车道。各套组以颜色区分，可将 3.0 m/2.5 m/C/nn 体系相互比对 |
| 8 | 选择荷载传递方式（Lane element / Cross beam distribution）后点击 **Create** — 一次性写入整套，并通过再次读取确认有无遗漏。以同一前缀重跑时覆盖写入，新前缀则作为独立套组添加 |

## 参考/限制事项

- 特殊车辆宽度须取自 CS 458，Plug-in 无法自动计算，故每次运行都需手工输入。
- 删除若用名称过滤器，API 会忽略过滤器而清空整张表，故始终只能按重新读取到的 key 执行。
- 斜（skew）角度仅在选择 Cross beam distribution 时可输入（与 MIDAS 对话框的限制相同）。
- Lane element distribution 把荷载直接施加到车道经过的单元上，Cross beam distribution 则通过横构件结构组
  分配荷载 —— 梁格模型或 Plug-in 生成的基准梁（只有少数几个节点）需要后者。

## 结论（原文）

CS 454 Auto Lane Generator 消除了为评估准备桥梁横断面时那些缓慢而机械的工作 —— 计算 Table 5.9a·Equation 5.18 对特定车行道宽度给出的取值、区分并维护三套车道体系、把特殊车辆布置在伴随交通旁边、校核所有偏心的符号、为基准线经过的每个单元输入 Lane Item。但它并不代替工程判断：车行道宽度、基准线路径、评估活荷载等级、结构应承受的荷载、荷载传递方式均须由用户决定，而其中每一项在写入模型之前都会先以图纸·尺寸·清单的形式给出。对于像 cl 5.5.1 那样 CS 454 把事项移交其他文件（CS 458）处理的情况，Plug-in 也不会悄然替其作答，而是明确予以说明。
